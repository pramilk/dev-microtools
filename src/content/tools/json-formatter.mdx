faq:
  - q: Is my JSON sent to a server?
    a: No. The formatting, validation and sorting all happen in JavaScript inside your own browser tab. No network request is made with your data, which means it is safe to paste API responses containing tokens or personal information. You can confirm this yourself by opening your browser's Network tab while using the tool — you will see no outbound requests.
  - q: Why does sorting keys leave my arrays in the original order?
    a: Because array order is data, not formatting. Reordering the elements of an array changes what the document means, so this tool deliberately never touches it. Only the keys within objects are sorted, since JSON object key order carries no semantic meaning per the specification.
  - q: What does the error message mean when it mentions a position?
    a: The position is the character offset in your input where the JSON parser encountered something it could not handle. It is usually a few characters after the actual mistake — a missing comma or an unclosed bracket earlier in the document often only becomes unparseable later on. Look slightly before the reported position.
  - q: Can it handle very large JSON files?
    a: It handles files of a few megabytes comfortably. Because everything runs in your browser tab, extremely large documents (tens of megabytes) may make the page feel sluggish while parsing, since the work competes with rendering on the same thread. For files that size, a command-line tool such as jq is a better fit.
  - q: Does it support JSON5, comments, or trailing commas?
    a: No. This tool validates against the strict JSON specification, which does not permit comments or trailing commas. That is deliberate — if your document parses here, it will parse in any standards-compliant JSON parser. If you need comments in configuration, JSONC or YAML are better formats for that purpose.

## A note on validation

"Valid JSON" is a narrower category than most people expect. Single quotes around strings,
unquoted object keys, trailing commas and `//` comments are all common in JavaScript object
literals and all invalid in JSON. If you are hand-writing a JSON file and it will not parse,
those four are worth checking before anything else.
