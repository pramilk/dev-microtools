faq:
  - q: Where do I find the secret key for my account?
    a: When a site offers two-factor authentication it shows a QR code, and usually a link beside it such as "Can't scan it?" or "Enter this key manually". That reveals the secret as a base32 string. Copy it from there at setup time, since most sites will not show it again afterwards. If you only have the QR code, a QR reader gives you an otpauth link that you can paste straight into this tool.
  - q: Is it safe to put my real secret into this page?
    a: The calculation runs locally and nothing is sent anywhere, stored, or put in the page address. Even so, anyone who holds a secret can generate your login codes, so for a high-value account such as your bank or main email, use your authenticator app rather than pasting the secret into any web page.   - q: Why does a valid-looking code get rejected by the server?
    a: The usual causes are a clock that is off by more than about thirty seconds, a mismatch in settings (the algorithm, digit count or period), a mistyped secret, or typing the code after it has already rolled over. Check the countdown, compare the settings on both sides, and use Check a code, which also tells you whether you entered the previous or next code by mistake.
  - q: What do the algorithm, digits and period settings mean?
    a: Almost every service uses SHA-1, six digits and a thirty-second period, and so does every authenticator app by default. SHA-256 and SHA-512, seven or eight digits, and other periods exist in the standard, but many apps ignore them and silently use the defaults. Only change them if the service tells you to, and test the result in the app you will use.
  - q: Why is a short secret flagged?
    a: The standard requires at least 128 bits, which is 26 base32 characters, and recommends 160 bits. A shorter secret is easier to guess and some authenticator apps refuse to import it. Press Generate secret to create a 160-bit one using your browser's secure random number generator.
  - q: How is this different from HOTP?
    a: HOTP, defined in RFC 4226, uses a counter that increases each time a code is used. TOTP, the version this tool handles, replaces the counter with the current time divided into steps, so a code expires on its own. A link for a counter-based code starts with otpauth://hotp/ and is rejected with an explanation, since it needs a different workflow.

## How the code is calculated

A one-time password is a short digest of two things both sides already know. The secret is
a random value shared when you set up two-factor authentication. The counter is the current Unix
time divided by the period, so with the usual thirty-second period it ticks up once every thirty
seconds. The tool runs an HMAC of the counter keyed with the secret, picks four bytes from the
result using the dynamic-truncation rule, and keeps the last six digits. Because both sides
repeat the same steps, they get the same number without ever sending it.

## Where to find the secret and how to use it

Wherever a site shows a QR code for two-factor setup, look for **Can't scan it?** or **Enter this
key manually**. The text key is the base32 secret. Paste it into the Secret box with or without
spaces and in any case. You can also paste a complete `otpauth://` link, which carries the secret
and the settings together.

If you would rather start from scratch, press **Generate secret**, give the account a name and
scan the QR code with your authenticator. The first code it shows should match the one on this
page. If it does not, check that your device clock is correct.
