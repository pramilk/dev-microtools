whatIsIt: >-
  Base58 encodes arbitrary bytes using 58 printable characters instead of the 64 that
  Base64 uses. It deliberately excludes the digit "0", the letters "O" and "I", and the
  lowercase "l" — characters that are easy to confuse with one another or with "1" in many
  fonts. That makes Base58 strings safer to read aloud, write down, or retype by hand,
  which is exactly why it was designed for Bitcoin addresses and later adopted by IPFS
  content identifiers (CIDv0) and several other systems that need compact, human-copyable
  identifiers. This tool converts text or arbitrary data to and from Base58 entirely in
  your browser, so you can inspect what a Base58 string actually decodes to, or produce
  one from data you already have.
useCases:
  - Decoding a Bitcoin or other cryptocurrency address to inspect the raw bytes it encodes, for debugging or learning purposes.

  - Converting an identifier from a Ripple/XRP address or similar system that uses the same base58btc alphabet.
  - Encoding arbitrary text or binary data into a compact, visually unambiguous string for manual transcription.

faq:
  - q: Why does Base58 exclude 0, O, I and l?
    a: Satoshi Nakamoto chose this alphabet for Bitcoin specifically to avoid characters that look alike in common fonts — the digit zero and capital O, and the capital I, lowercase l and the digit one. Bitcoin addresses are sometimes copied by hand or read aloud, and a single misread character there is a real, unrecoverable-funds problem. Dropping the four lookalikes removes that entire class of mistake.
  - q: How is Base58 different from Base64?
    a: Base64 uses a 64-character alphabet including "+", "/" and "=" padding, which is more space-efficient but includes characters that behave badly inside URLs and can break with a double-click text selection. Base58 uses a smaller 58-character alphabet with no punctuation and no visually ambiguous characters, which makes it friendlier for manual copying at a small cost in output length — Base58 output runs slightly longer than Base64 for the same input.
  - q: Why did a leading zero byte turn into a "1" in the output?
    a: Base58 treats the input bytes as one large number and converts it to base 58, but a leading zero byte has no effect on that number's value — it would simply vanish. To preserve it, the algorithm maps each leading 0x00 byte to a leading "1" character (the alphabet's zero-index symbol) before the numeric digits. This is the detail most from-scratch Base58 implementations get wrong.
  - q: Is it safe to paste a private key or seed phrase into this tool?
    a: This tool runs entirely in your browser and never transmits what you paste anywhere, but that is not a reason to paste a real private key or seed phrase into any browser-based tool, including this one. Treat secrets like that the way you would treat a physical key — copying them into text fields, clipboards, or browser tabs is a bad habit to get into regardless of what any individual tool promises to do with the data.
  - q: What does this tool do with my input?
    a: Nothing leaves your browser. Encoding and decoding both happen locally in JavaScript, with no network request involved — this is true of every tool on this site, not just this one.

## Not a wallet or key-generation tool

This tool encodes and decodes bytes you already have — it does not generate cryptographic
keys, derive addresses, or validate checksums the way a real wallet would. If you paste in
a Bitcoin address, you get back the raw bytes it encodes; this tool makes no claim about
whether that address is valid, funded, or belongs to anyone. Use it to understand what a
Base58 string contains, not to produce one you intend to use as a real credential.
