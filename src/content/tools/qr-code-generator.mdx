faq:
  - q: What does the error correction level actually control?
    a: 'It controls how much of the code can be damaged, dirty, or obscured (for example by a logo placed on top) and still scan correctly: roughly 7% at Low, 15% at Medium, 25% at Quartile, and 30% at High. Higher levels add more redundant data, which makes the code physically denser for the same content — Medium is a sensible default for most uses, High if you plan to overlay a logo.'
  - q: Is there a limit to how much text a QR code can hold?
    a: Yes — this tool caps input at 1,500 characters, comfortably under what the QR standard supports at low error correction, but a QR code storing that much text becomes very dense and harder for cheap cameras to read reliably. For anything beyond a short message, encoding a short URL that points to the full content scans far more reliably.
  - q: Why would I choose SVG over PNG?
    a: SVG is a vector format, so it stays perfectly sharp printed at any size — a business card or a building-sized banner both render cleanly from the same file. PNG is a fixed-resolution raster image, better suited to sharing on screen (chat, slides, social posts) where a vector format usually isn't accepted directly.
  - q: Does generating a QR code here send my data anywhere?
    a: No. The QR code is built entirely in your browser from a small, open-source encoding library, and the image itself is produced on an in-page canvas. Nothing you type is uploaded, logged, or sent to a server — that's true even for the finished PNG or SVG, which are saved directly from your browser to your device.
  - q: My QR code isn't scanning — what's wrong?
    a: The most common cause is insufficient contrast or the code being printed too small for its density — a long URL at Low error correction produces a fine grid that struggles at business-card size. Try a shorter URL (a link shortener helps), a higher error correction level if you're adding a logo, or simply printing it larger.
  - q: Which payment apps does the Payment mode support?
    a: PayPal, Venmo, and Cash App — each has a real link format that opens straight into a pre-filled payment screen when scanned, built from just the recipient's username and an optional amount. Apple Pay, Google Pay, and Zelle don't offer any public link format a third party can construct (Zelle's QR codes are generated inside your banking app and tied to your bank enrollment), so they aren't included here. If you already have a Stripe or Square checkout link — a full URL your Stripe or Square dashboard generated for you — use Text/URL mode instead; it's already a plain link and needs no special handling.

## Choosing what to encode

A QR code that encodes a full, long URL works, but produces a denser, harder-to-scan
pattern than one encoding a short link. If a URL is long — with tracking parameters, for
instance — consider generating the code from a shortened version instead.
