faq:
  - q: Is my PDF or my password uploaded anywhere?
    a: No. The PDF is read, decrypted and written entirely in your browser, in a background worker, and the password is only held in the page and that worker. Nothing is transmitted. You can disconnect from the internet after the page loads and the tool still works.
  - q: Can this recover a password I forgot?
    a: No. This tool only removes protection when you supply the correct password. It never tries to guess or crack one, and with a modern AES-256 file nothing realistically can if the password is strong. If you have lost the password, ask whoever sent the file for a fresh copy or the password.
  - q: What is the difference between the open password and the permissions password?
    a: The open password is needed to view the file at all. The permissions password, also called the owner password, is the one that lets you change the restrictions on printing, copying and editing. Either one unlocks the file here. Many files have restrictions but no open password, and those open without any password while still blocking some actions.
  - q: Why does it ask me to confirm before removing restrictions?
    a: Restrictions are the author's wishes about what readers may do. When you only have the open password, removing them is not something the author granted you, so the tool asks you to confirm you own the document or have permission. The permissions password needs no confirmation because it exists for exactly this purpose. Check the rules that apply to the document you are working with.
  - q: Which kinds of encryption can it read?
    a: Standard password protection in all its versions, meaning RC4 with 40-bit and 128-bit keys, AES-128, and AES-256 in both its original and its current form. It cannot read PDFs locked with a digital certificate or a rights-management system, such as Adobe LiveCycle or FileOpen, because those do not use a password. It tells you when it meets one.
  - q: Will bookmarks, links, forms and images survive?
    a: Yes. The tool decrypts the file's contents rather than rebuilding the pages, so text, images, fonts, bookmarks, links, form fields and metadata come through unchanged. A digitally signed PDF is the exception, because a signature covers the exact bytes of the original, so it will not verify in the unlocked copy, and the tool tells you when that applies.
  - q: Why is the unlocked file a different size?
    a: Decrypting removes the encryption overhead, which is small, and the file is written again in a compact layout, so the size usually changes by a few percent either way. If you want it smaller, run it through the PDF Compressor afterwards.
  - q: Is there a limit on file size?
    a: The PDF can be up to 150 MB. Everything is held in your device's memory while it is decrypted, so a very large file may take a few seconds on a slow phone.

## What it does to the file

An encrypted PDF stores every string and stream as scrambled bytes, plus a small security
record that says how, with values derived from the password. This tool checks your password
against that record. If it matches, it recovers the file's encryption key, decrypts each
string and stream, removes the security record and writes the result as a normal PDF.
Nothing is re-rendered, so pages look identical to the original.

## The compressed layout

PDF software since about 2005 packs most of the file's small objects into compressed
containers, and encrypts each container as a whole. Reading such a file means decrypting the
containers before unpacking what is inside them, which is the step simple tools get wrong.
This tool handles it, and the result was checked against files written by qpdf, an
independent implementation, for every encryption version above, with and without that layout.

## What powers this tool

PDF parsing and writing use [`pdf-lib`](https://github.com/Hopding/pdf-lib) (MIT licensed),
which cannot decrypt on its own, so the decryption is written for this site on top of the
audited AES and SHA-2 primitives in [`@noble/ciphers`](https://github.com/paulmillr/noble-ciphers)
and [`@noble/hashes`](https://github.com/paulmillr/noble-hashes). Both run in a background
Web Worker that is only loaded once you choose a file.
