  malicious link, and lets you enter the address you expected so it can confirm the code

faq:
  - q: How can I tell if a QR code is dynamic or static?
    a: A static QR code stores the final address directly, so decoding it shows your real domain. A dynamic one stores a short link on the vendor's domain and the vendor redirects it. Scan the code with this tool and look at the domain. If it is not the website you expected, the code is dynamic. The practical difference is that a static code cannot expire, while a dynamic one works only as long as the vendor keeps redirecting it.
  - q: Why did my QR code start charging me or stop working?
    a: Dynamic QR services often offer a free trial and then require a subscription to keep the redirect running. When the trial ends or a payment fails, the vendor can disable the link or show their own page instead, and the printed code gives you no way around it. The fix is to create a new static code that contains your real address, using the QR Code Generator on this site, and reprint it.
  - q: Does this tool follow the link and show the final destination?
    a: No. It never contacts the address, which is also why nothing you scan is sent anywhere. It reports what is written inside the code, and when the code contains a redirect parameter it shows the address hidden in it. It cannot see what a server does after you open the link, so a normal-looking address can still redirect. To follow a redirect safely, use a link-expanding service in a sandboxed environment rather than opening it directly.
  - q: Is a code marked "direct" safe to open?
    a: Not necessarily. Direct means the code contains no short-link, dynamic-QR or redirect wrapper. It says nothing about whether the site itself is trustworthy. The tool still flags warning signs such as http without encryption, raw IP addresses, look-alike characters and brand names on unrelated domains, but a clean result is not a guarantee. Check that the domain is the one you expect.
  - q: Can it read codes that are not links, such as Wi-Fi or payment codes?
    a: Yes. It identifies Wi-Fi logins, payment requests, contacts, phone numbers, emails and two-factor secrets, and explains what scanning would do. The share-link button is hidden for Wi-Fi, payment and two-factor codes because a shared URL would carry the password or secret inside it.
  - q: Why can't it find the QR code in my photo?
    a: The reader needs the whole code, its quiet white border, and enough sharpness to separate the modules. Blurry, heavily angled, glared or very small codes can fail, as can images that contain several codes, since only one is read. Crop to the single code, take the photo straight on, and try again.

## Why the domain is the whole story

The single most useful fact about a QR code is the domain it contains. If the domain is
yours, or the organisation you expect, the code is as permanent as that website. If it
belongs to a QR vendor or a link shortener, your code lasts only as long as their service,
account and pricing do. This tool puts that domain at the top and explains what it means.

## Replacing a dynamic code

If the checker shows a dynamic-QR domain on a code you own, make a replacement that holds
your real address with the [QR Code Generator](/qr-code-generator/), test it with this
tool, and reprint. You give up scan analytics and the ability to change the destination
without reprinting, which are the things dynamic services charge for.

## What the checks look for

The tool recognises well-known dynamic-QR and short-link domains, destinations tucked
inside redirect parameters, and tracking parameters such as `utm_source` or `fbclid`. It
also flags credentials placed before the host (`https://trusted.com@evil.example`),
international look-alike characters, raw IP addresses, unusual ports, plain `http`, and
script-style schemes such as `javascript:`. Paste a full address into the
[URL Parser](/url-parser/) if you want every component broken out.
